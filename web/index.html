01 / WHAT IS THIS
무엇을 하는 프로그램인가

Google Teachable Machine에서 직접 학습시킨 이미지 분류 모델을, 브라우저 안에서 웹캠이나 이미지에 적용해 보는 판독 보조 도구입니다. 학습 기능은 없습니다 — 모델은 Teachable Machine에서 만들고, 이 프로그램은 그 모델을 불러와 쓰고 · 검증하고 · 기록하는 역할만 합니다.

CORE
이 프로그램의 목적은 "정확도 자랑"이 아닙니다. 모델이 확신하지 못할 때 확신하지 않는다고 말하게 만드는 것, 그리고 왜 그렇게 판단했는지 근거를 남기는 것입니다. 그래서 판정을 5가지 상태로 나누고, 유사도·불확실성·근거 히트맵을 함께 보여줍니다.

한 번의 판독이 지나는 5단계

  • ① 품질 검사 — 초점·밝기·대비를 재서 판독에 부적합한 영상이면 경고합니다.
  • ② 224 정사각 변환 — 모델이 보는 영역만 잘라 224×224로 축소합니다. 이 영역을 화면에 그대로 표시합니다.
  • ③ 게이트키퍼(선택) — "판독 대상이 맞는지"만 판단하는 별도 모델이 앞에서 막습니다.
  • ④ 주분류기 + 앙상블 — 여러 모델의 출력을 가중 평균해 클래스별 유사도를 만듭니다.
  • ⑤ 판정 — 4개 관문을 통과한 것만 결론으로 발표합니다.
PRIVACY
추론·품질 측정·히트맵 전부 이 브라우저 안에서만 실행됩니다. 촬영·업로드한 영상은 서버로 전송되지 않습니다. 이력에도 원본이 아니라 96px 썸네일과 숫자만 남습니다.

04 / READING
판독 화면 사용법

이미지를 넣는 3가지 방법

  • 끌어다 놓기 — 파일을 점선 영역 안에 떨어뜨립니다.
  • 클릭해서 선택 — 점선 영역을 클릭하면 파일 선택창이 열립니다. Enter 또는 Space 로도 열립니다.
  • 내장 샘플 — 아래쪽 SAMPLE 줄의 버튼을 누르면 미리 넣어 둔 이미지가 바로 올라갑니다. 발표 중에는 이걸 쓰세요 — 파일 탐색기를 열 필요가 없고 업로드가 실패할 일도 없습니다.
SAFE
업로드가 실패하면 내장 샘플이 자동으로 올라옵니다. 데모가 중간에 끊기지 않도록 넣어 둔 대비 장치입니다. 샘플이 비어 있으면 cd prep && python3 make_samples.py 로 만드세요.

★ 초록 박스 — 모델이 실제로 보는 영역

미리보기 위에 표시되는 사각형은 장식이 아닙니다. 박스 안쪽만 잘라내 224×224로 축소해 모델에 넘깁니다. 박스 밖은 모델에 전달되지 않습니다.

LIMIT
Teachable Machine은 입력을 224×224로 축소합니다. 원본에서 10픽셀 정도인 미세 병변은 이 과정에서 1픽셀 수준으로 뭉개져 사라집니다. 작은 병변을 다루는 주제라면 이것이 근본적 한계이며, 발표에서 반드시 언급해야 하는 항목입니다 (도움말 12번 참조).

품질 지표 4개

이미지를 올리면 자동으로 측정됩니다. 기준을 벗어나면 경고가 뜨지만 판독은 그대로 진행됩니다 — 사용자가 의도적으로 올린 파일이기 때문입니다.

  • 품질점수 — 아래 3개를 종합한 0~100 점수. 70 이상이면 초록입니다.
  • 초점 — 높을수록 선명합니다. 낮으면 흐린 영상입니다. 강의 7-1에서 "초점 흐림·너무 어두운 이미지는 학습 초반엔 제외하는 게 좋다"고 한 그 기준입니다.
  • 밝기 — 허용 범위 밖이면 경고합니다. 너무 어두우면 노이즈가, 너무 밝으면 정보가 날아갑니다.
  • 대비 — 너무 낮으면 판독 대상이 없거나 균일한 면만 찍힌 상태입니다.

이 값들은 어떤 영상이 판독에 부적합한지 설명할 근거가 됩니다. "이 데이터셋은 화질 편차가 커서 초점 지표가 60 미만인 영상이 N% 있었습니다" 같은 문장을 발표에 쓸 수 있습니다.

★ 근거 히트맵 — 가장 중요한 검증 도구

판독한 뒤 분석 시작을 누르면, 이미지를 8×8 격자로 나눠 한 칸씩 가리고 다시 추론합니다(총 64회, 1~3초). 가렸을 때 유사도가 크게 떨어진 칸이 모델이 근거로 삼은 영역이며 붉게 표시됩니다.

CHECK
붉은 영역이 병변이 아니라 이미지 구석·글자·촬영 프레임·눈금자에 몰려 있으면 지름길 학습(shortcut learning)입니다. 정확도가 높아도 실제로는 쓸 수 없는 모델입니다.

강의 6-2의 실제 사례: 촬영 프레임이 크게 남은 이미지들이 특정 클래스에 몰려 있어, 모델이 병변이 아니라 "프레임이 큰지 여부"로 판단했습니다. 강의 6-3은 "Teachable Machine은 블랙박스라 정성적 비교가 사실상 유일한 검증 수단" 이라고 했지만, 이 히트맵은 그것을 수치로 확인해 줍니다. 발표에서 강한 카드입니다.

해석 문장이 자동으로 판정을 알려 줍니다 — 예: "근거의 68%가 이미지 주변부에 몰려 있습니다 — 병변이 아닌 촬영 조건을 학습한 지름길 가능성을 의심하세요." 이 경고가 나오면 전처리에서 여백·글자를 잘라내고 다시 학습해야 합니다.

항상 표시되는 것

  • DATASET 카드 — 데이터 출처·라이선스·라벨링 방식·클래스 구성. 대회 필수 표기 항목입니다.
  • SAFETY — "교육용 프로토타입이며 실제 진단·치료에는 사용할 수 없습니다".
  • PRIVACY — 영상이 브라우저 밖으로 나가지 않는다는 사실.
  • 판독 시각과 그때 적용된 임계값 — 사후에 판정을 재현할 수 있게 합니다.

'구분 어려움'이 안 나오는 것은 고장이 아닙니다. 모델 출력의 합은 항상 1이므로, 1위가 70%면 2위는 최대 30% — 즉 차이가 최소 40%p입니다. 그래서 기준 15%는 절대 걸리지 않습니다. 이 상태는 보류 임계값을 낮췄을 때만 활성화됩니다. 설정 탭이 현재 조합에서 발동 가능한지, 안 되면 어떤 값으로 바꿔야 하는지 알려 줍니다.
06 / READING THE NUMBERS
숫자 읽는 법
FIRST
화면의 모든 퍼센트는 "확률"이 아니라 "유사도"입니다. "이 병일 확률 78%"가 아니라 "학습시킨 클래스와 78% 닮았다"는 뜻입니다. 이 둘은 완전히 다릅니다. 발표할 때도 이 표현을 지키세요.
유사도TOP SIMILARITY
1위 클래스의 원시 출력값. 모델이 말하는 그대로의 숫자입니다. 과신하는 경향이 있습니다 — 그래서 아래 보정 신뢰도가 필요합니다.
보정 신뢰도CALIBRATED
"모델이 이 정도라고 말한 예측들의 실제 정답률"입니다. 모델이 90%라 했는데 실측이 68%면 68%를 보여줍니다. 성능 평가 탭에서 보정표를 생성해야 나타납니다.
1·2위 차이MARGIN
1위와 2위의 격차. 작으면 모델이 두 클래스를 헷갈리고 있다는 뜻입니다. 60%p 차이로 1위인 것과 3%p 차이로 1위인 것은 완전히 다릅니다.
불확실성ENTROPY 0~1
0이면 완전히 확신, 1이면 모든 클래스가 똑같이 보인다는 뜻입니다. 0.5를 넘으면 주의해서 보세요.
흔들림JITTER
웹캠 실시간 판독에서만 쓰이는 값입니다. 이미지 업로드는 정지 영상 1장이므로 — 로 표시됩니다.
민감도SENSITIVITY
놓치지 않는 능력. 실제 이상인 것 중 몇 %를 이상으로 잡아냈는지. 놓치면 위험한 소견을 다룰 때 가장 중요한 지표입니다.
특이도SPECIFICITY
정상을 정상으로 보는 능력. 낮으면 멀쩡한 것을 계속 이상이라고 해서 사람이 확인할 일이 폭증합니다.
보류율HOLD RATE
전체 중 몇 %를 "판단 보류"로 넘겼는지. 너무 높으면(40%↑) 실용성이 없고, 0%면 모델이 과신하고 있을 가능성이 있습니다.
07 / EVALUATION
성능 평가 사용법

Teachable Machine이 보여주는 정확도는 발표에 쓰면 안 됩니다. TM은 학습/검증 데이터를 우리가 나눌 수 없어서, 같은 원본에서 만든 변형본이 양쪽에 섞이면 정확도가 부풀려집니다. 여기서 TM에 넣지 않은 데이터로 직접 검증한 수치가 진짜입니다.

폴더를 준비하는 방법

평가용 폴더는 클래스 이름과 똑같은 이름의 하위 폴더로 나눠야 합니다.

holdout/
├── normal/        ← 폴더 이름 = 클래스 id (대소문자까지 동일)
│   ├── 0001.png
│   └── 0002.png
├── abnormal/
├── borderline/
└── invalid/
TOP MISTAKE
Normal/ 과 normal/ 은 다른 폴더로 인식됩니다. 실습에서 가장 많이 발생하는 사고입니다. 폴더를 넣으면 프로그램이 먼저 정합성을 검사해 불일치를 알려 주니, 초록색 확인 메시지가 뜬 뒤에 결과를 믿으세요.

임계값 슬라이더 — 이 대회의 승부처

슬라이더를 움직이면 다시 추론하지 않고도 민감도·특이도·보류율이 즉시 바뀝니다. 확률 벡터를 이미 갖고 있기 때문입니다. 이건 취향 문제가 아니라 임상 판단입니다.

  • 임계값을 올리면 → 확정 판정이 줄고 보류가 늘어납니다. 사람이 볼 일이 많아지지만 놓치는 건 줄어듭니다.
  • 임계값을 내리면 → 과감하게 판정합니다. 편하지만 틀릴 위험이 커집니다.
  • Youden 균형점 — 민감도와 특이도의 합이 가장 큰 지점을 자동으로 찾습니다.
  • 민감도 95% 확보 — "95% 이상은 반드시 잡아낸다"를 만족하면서 위양성이 가장 적은 지점입니다.

보류 처리 정책 — 두 숫자가 완전히 달라집니다

정책의미어디에 쓰나
escalate 보류를 "양성 의심으로 사람에게 넘김"으로 계산합니다. 민감도에 유리하고 특이도에 불리합니다. 실제 운영 지표. 임상적으로 안전한 쪽이라 발표에는 이 값을 쓰세요.
exclude 보류를 아예 계산에서 제외합니다. 확정 판정만 평가한 순수 모델 성능입니다. 모델 자체를 비교할 때. 반드시 보류율을 함께 밝혀야 정직합니다.

순서대로 하면 되는 일

  • 폴더 드롭 → 정합성 초록 확인 → 배치 완료까지 대기
  • 보정표 생성 클릭 → 판독 화면에 보정 신뢰도가 나타납니다
  • 임계값 슬라이더로 운영점 결정 → 판독에 적용
  • 자세히 보기를 펼쳐 혼동행렬로 어느 클래스끼리 헷갈리는지 확인
  • 실패 사례를 눈으로 확인 → CSV로 내보내 보고서에 첨부
08 / COMMON MISTAKES
자주 하는 실수
실수왜 문제인가어떻게 해야 하나
무효 입력 클래스를 안 만듦 모델은 손·벽을 비춰도 반드시 무언가를 답합니다. 출력 합이 항상 1이라서요. 심사위원이 손을 흔들면 "이상 소견 87%"가 뜹니다. 가장 중요한 대비책입니다. 배경·손·초점불량 이미지를 모아 별도 클래스로 학습시키세요.
클래스 이름 오타 TM 클래스명과 설정의 id가 한 글자만 달라도 결과가 엉뚱하게 표시됩니다. 설정 탭의 클래스 정합성이 초록색인지 확인하세요.
학습 데이터와 촬영 환경이 다름 스캔 이미지로 학습하고 웹캠으로 판독하면 조명·압축·왜곡이 달라 정확도가 무너집니다. 웹캠으로 판독할 거면 학습 데이터도 웹캠 환경에 맞게 준비하세요.
대상을 가이드 박스 밖에 둠 박스 밖은 잘려서 모델에 전달되지 않습니다. 모델은 배경만 보고 답합니다. 대상을 박스 안에 꽉 채우세요.
TM 정확도를 그대로 발표 학습/검증 분할을 통제할 수 없어 부풀려진 값입니다. 성능 평가 탭의 수치를 쓰세요. TM보다 낮게 나오는 게 정상입니다.
클래스를 너무 많이 만듦 클래스가 늘수록 각 클래스의 데이터가 부족해지고 서로 헷갈립니다. 3~4개로 줄이세요. 혼동행렬에서 자주 헷갈리는 쌍은 합치는 게 낫습니다.
클래스별 장수가 크게 불균형 TM은 불균형을 보정하지 않습니다. 많은 클래스로 편향됩니다. 클래스마다 비슷한 장수로 맞추세요.

10 / FAQ
자주 묻는 질문

모델을 여기서 학습시킬 수 있나요?

아니요. 학습은 Teachable Machine에서 하고, 이 프로그램은 만든 모델을 불러와 쓰기만 합니다.

인터넷 없이 쓸 수 있나요?

안 됩니다. 추론 라이브러리와 모델을 인터넷에서 받아옵니다. 단 영상은 전송되지 않습니다 — 받아오기만 합니다.

제 사진이 서버로 올라가나요?

아니요. 모든 처리가 브라우저 안에서 끝납니다. 이력에도 96px 썸네일과 숫자만 남습니다.

앙상블은 왜 쓰나요?

서로 다르게 전처리한 데이터로 학습한 모델 여러 개의 출력을 평균하면 단일 모델보다 안정적입니다. 클래스 구성이 완전히 같아야 하며, 다르면 경고가 뜹니다.

게이트키퍼는 꼭 필요한가요?

필수는 아닙니다. 무효 입력 클래스만으로도 상당히 해결됩니다. 다만 둘을 함께 쓰면 훨씬 견고해집니다 — 하나는 데이터로, 하나는 구조로 막는 방식입니다.

이력은 얼마나 남나요?

최근 300건입니다. 실시간 모드에서는 판정이 확정된 순간에만 기록되어 초당 여러 건이 쌓이지 않습니다.

웹캠으로도 쓸 수 있나요?

기능은 들어 있지만 기본적으로 꺼져 있습니다. 이 대회의 기준 시나리오는 이미지 업로드이고, 쓰지 않을 기능을 화면에 두면 오히려 감점 요인이 되기 때문입니다. 필요하면 project.config.js 의 ui.enableWebcam 을 true 로 바꾸면 입력 선택 탭과 실시간 판독이 되살아납니다.

단축키가 있나요?

⌘K 또는 Ctrl+K 로 명령 팔레트가 열립니다. 화면 이동, 판독 실행, 근거 분석, 보정표 생성, CSV 내보내기를 검색해 실행할 수 있습니다.

특정 화면을 바로 열 수 있나요?

주소 끝에 #console/eval 처럼 붙이면 됩니다. #overview · #console/read · #console/hist · #console/set · #console/help 를 쓸 수 있어 시연 중 원하는 탭을 즉시 띄울 수 있습니다.

11 / MUST READ
반드시 지킬 것

  • 약점을 먼저 드러내세요. 실패 사례와 보류율을 숨기지 않는 것이 오히려 신뢰를 얻습니다.

한계가 없는 모델은 없습니다. 중요한 것은 해결이 불가능한 근본적 한계와 다음 단계에서 해결 가능한 한계를 구분해 설명하는 것입니다. 구분해서 말하면 "모델이 언제 어디서 틀리는지 정확히 알고 있다"는 증거가 됩니다.
