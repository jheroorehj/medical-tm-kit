# medical-tm-kit

Teachable Machine 기반 의료영상 분류 서비스의 **주제 무관 프레임워크**.

주제가 확정되기 전에 만들 수 있는 모든 것을 미리 만들어 둔 것입니다. TM의 제약을
우회하는 로직은 "폐렴인지 피부병변인지"를 알아야 만들 수 있는 게 아니기 때문입니다.
주제가 정해지면 **설정 파일 2개**만 고치면 전체가 새 주제로 돌아갑니다.

현재 화면은 Claude Design 에서 만든 **RADIOLENS** 디자인(1440px 고정폭, 랜딩 +
5탭 콘솔)을 구현한 것입니다. 입력은 **이미지 업로드**이며(대회 기준),
웹캠은 `ui.enableWebcam` 으로 껐습니다. 직접 다시 만들 경우 **`FRONTEND-SPEC.md`** 를 보세요 —
`web/js/` 의 로직 모듈 11개는 DOM을 거의 모르므로 그대로 재사용하고 화면만 새로
만들면 됩니다.


**처음 쓰는 사람은 앱의 `도움말` 탭부터 보세요** — 환경을 자동 점검해 무엇이 막혔는지

저장되는 6단계 체크리스트, 판정 5상태 해설, 용어 사전, 자주 하는 실수 7가지,
오류 해결 사전 14항목, FAQ, 안전 주의사항이 들어 있습니다.

**딥링크**: `#overview` · `#console/read` · `#console/eval` · `#console/hist` ·
`#console/set` · `#console/help` 로 특정 화면을 바로 열 수 있습니다. 시연 중 원하는 탭을 즉시
띄우거나 북마크해 두는 용도입니다. `⌘K`(또는 `Ctrl+K`)로 명령 팔레트가 열립니다.

## 1. 이 구조가 왜 이런 모양인지

Teachable Machine은 **MobileNet 특징 추출기를 고정하고 마지막 분류층만 학습하는
전이학습기**입니다. 여기서 모든 제약이 파생되고, 이 킷의 모든 기능은 특정 제약에
대한 대응입니다.

| TM의 제약 | 대응 | 위치 |
|---|---|---|
| 입력이 224×224 — 큰 영상의 병변이 소실 | ROI 크롭 · 여백 자동 제거 · 가장자리 트림 | `pipeline.py` |
| 특징 추출기 고정 — 저대비 병변을 못 봄 | CLAHE 대비 보정 | `pipeline.py` |
| **데이터 증강 기능이 없음** | 회전·밝기·노이즈·블러 외부 생성 | `augment.py` |
| 학습 도메인 ≠ 웹캠 추론 도메인 | **웹캠 열화 증강** + **실제 재촬영** | `augment.py` `recapture.py` |
| **softmax가 항상 억지 답을 냄** | 무효 클래스(데이터) + 게이트키퍼(구조) | `negatives.py` · 웹앱 |
| **학습/검증 분할을 통제 못 함 (누출)** | 원본 단위 홀드아웃 + 자체 평가 | `pipeline.py` · 웹앱 |
| 중복 이미지로 정확도 부풀려짐 | dHash 근중복 제거 | `pipeline.py` |
| 클래스 불균형 보정 없음 | 그룹 단위 균형 조정 · `--target` | `pipeline.py` `augment.py` |
| Grad-CAM 없음 — 근거를 볼 수 없음 | **오클루전 히트맵** | 웹앱 |
| softmax를 확률로 착각하게 됨 | **신뢰도 캘리브레이션** | 웹앱 |
| 프레임 단위 예측이 심하게 흔들림 | 이동평균 + 연속 K프레임 확정 | 웹앱 |
| 나쁜 프레임도 그대로 추론됨 | 품질 게이트 + 촬영 코칭 | 웹앱 |
| 분류만 가능 (검출·분할 불가) | — 주제 선정 시 통과시켜야 하는 조건 | — |

**요약: TM 자체는 거의 손댈 게 없습니다. 승부는 TM 앞(전처리·증강)과 뒤(서비스
레이어)에서 납니다.** 이 킷이 그 앞뒤입니다.

## 2. 빠른 시작

```bash
# 웹앱만 먼저 보기
./serve.sh
# → http://localhost:8000 (자동으로 열립니다)
```

> **`file://` 로 열지 마세요.** Chrome은 `getUserMedia`에 secure context를 요구하므로
> 카메라가 열리지 않고, ES 모듈 import도 CORS로 차단됩니다.
> `localhost` 또는 `https`(Vercel 배포본)가 필요합니다.

**대회 참가자는 먼저 [`HACKATHON.md`](HACKATHON.md) 를 보세요** — 평가 기준 대응표,
8분 데모 시나리오, 1페이지 기획서 양식, 당일 시간 배분이 정리되어 있습니다.
근거가 되는 강의 원문은 [`docs/바이오헬스AI_해커톤정리.md`](docs/바이오헬스AI_해커톤정리.md) 에 있습니다.

데이터 파이프라인:

```bash
cd prep
pip install -r requirements.txt
```

### 설치 검증 — 실제 데이터 없이 오늘 확인할 수 있습니다

```bash
# 1) 판정·지표·캘리브레이션 로직 검증 (60개 단정, 손계산 값과 대조)
node test-logic.mjs

# 2) 데이터 파이프라인 전체를 합성 더미로 왕복
cd prep
python3 make_testdata.py          # 환자 그룹·중복·번인텍스트·검은여백을 일부러 포함
python3 pipeline.py --clean       # 전처리 · 중복제거 · 원본단위 분할
python3 augment.py --factor 3 --webcam-degrade
python3 negatives.py --synthetic 60 --degrade 60
cat ../data/prepared/report.md

# 실제 데이터를 넣기 전에 data/ 를 비우세요
```

`make_testdata.py`가 만드는 더미는 원이 그려진 그림이라 dHash가 거의 동일합니다.
그래서 **중복 과다 제거 경고가 뜨는 것이 정상 동작 확인**입니다.

## 3. 주제가 정해졌을 때 고쳐야 할 것 — 체크리스트

### ① `prep/prep.config.yaml`

- [ ] `paths.raw` — 원본 데이터 위치
- [ ] `split.group_regex` — **가장 중요.** 환자당 여러 장이 있는 데이터셋이면 반드시
      지정하세요. 예: `^(patient\d+)`, `^(IM-\d+)`. 지정하지 않으면 같은 환자의
      다른 촬영본이 train/holdout에 흩어져 성능이 과대평가됩니다.
- [ ] `preprocess.center_crop` — 판독 대상이 영상의 어느 정도를 차지하는지에 맞춰 조정
- [ ] `preprocess.clahe.enabled` — 저대비 영상(X-ray, 내시경)이면 켜고, 색이 중요한
      주제(피부, 검사 스트립)면 값을 낮추거나 끄고 비교해 보세요
- [ ] `balance.max_per_class` — 브라우저 RAM 한계. 증강 배수를 곱한 값이 최종 업로드량

### ② `web/project.config.js`

- [ ] `meta` — 제목, 부제
- [ ] `classes` — **`id`가 TM 클래스명과 글자 하나까지 같아야 합니다.**
      틀리면 웹앱이 부팅 시 설정 탭에서 불일치를 잡아 줍니다
- [ ] 각 클래스의 `kind` — `positive`(발견해야 하는 이상) / `negative`(정상) /
      `invalid`(무효 입력). **`invalid`를 반드시 하나 두세요**
- [ ] `classes[].advice` — 그 판정이 나왔을 때 사용자가 할 다음 행동
- [ ] `decision.inferRoi` — **`prep.config.yaml`의 `center_crop`과 같은 값으로**
      (학습 전처리와 추론 전처리를 일치시키는 것이 정확도에 크게 기여합니다)
- [ ] `copy.safetyNote` — 주제에 맞게 수정. "확률"이 아니라 "유사도"라는 표현 유지 권장
- [ ] `copy.metricPriority` — 놓치면 위험한 주제면 `sensitivity`

모델 URL은 코드에 넣지 않아도 됩니다 — 웹앱 설정 탭에서 입력하면 브라우저에 저장됩니다.

## 5. 웹앱 기능

### 판독 탭

**웹캠 실시간 판독** — 프레임마다 추론하고 이동평균으로 평활화한 뒤, 연속 K프레임
동일 판정일 때만 결과를 확정합니다. 모델을 재학습하지 않고 실질 정확도를 올리는
방법입니다.

**품질 게이트 + 촬영 코칭** — 라플라시안 분산으로 초점, 평균 휘도로 노출, 표준편차로
대비를 실시간 측정합니다. 나쁜 프레임은 추론조차 하지 않고 *"조금 더 밝게" /
"초점을 맞춰 주세요"* 로 코칭합니다. 가이드 박스는 **모델이 실제로 보는 영역**
(`inferRoi`)을 정확히 반영합니다.

**4단 판정 관문** — 그냥 1위를 발표하지 않습니다.

```
관문 0  게이트키퍼가 막았는가?         → 판독 대상 없음
관문 1  무효 입력 클래스가 1위인가?     → 무효 입력
관문 2  1위 유사도 < 임계값?            → 판단 보류
관문 3  1·2위 차이 < 마진?              → 구분 어려움
통과                                   → 판정
```

> **관문 3에 관한 수학적 제약** — softmax는 확률의 합이 1입니다. 따라서
> `2위 ≤ 1 − 1위` 이고, `마진 ≥ 2 × 1위 − 1` 입니다. 1위가 0.70이면 마진은
> **최소 0.40**이므로, 마진 기준 0.15는 절대 걸리지 않습니다 — 관문 2가 항상 먼저
> 걸러냅니다. 관문 3은 `2 × 임계값 − 1 < 마진기준`, 즉 **임계값을 낮춘 민감도 우선
> 운영점에서만 활성화**됩니다. 설정 탭이 현재 조합에서 발동 가능한지, 안 되면 어떤
> 값으로 바꿔야 하는지 실시간으로 알려 줍니다.

**근거 히트맵 (오클루전 분석)** — 화면을 8×8로 나눠 한 칸씩 가리고 재추론합니다
(64회, 1~3초). 유사도가 크게 떨어진 칸이 모델이 근거로 삼은 영역입니다.

> 이 기능의 진짜 가치는 예쁜 히트맵이 아닙니다. **모델이 병변이 아니라 영상 구석의
> 글자·워터마크·장비 테두리를 보고 있었다는 사실을 발견하는 순간**입니다. 발견하면
> `edge_trim`이나 `center_crop`을 조정해 제거하고 재학습하세요. 실제 성능이 오릅니다.
> 히트맵 해석은 자동으로 판정해 알려 줍니다 ("근거의 68%가 주변부에 있습니다").

### 성능 평가 탭

홀드아웃 폴더를 드래그하면 전체를 자동 추론합니다. 폴더명이 정답 클래스입니다.

- **혼동행렬** + 클래스별 정밀도/재현율/F1
- **민감도 · 특이도 · 양성예측도 · 보류율** — 의료 도메인의 언어
- **임계값 슬라이더** — 움직이면 민감도·특이도가 실시간으로 갱신됩니다. `Youden J`로
  균형점을, `민감도 95% 확보점`으로 안전 우선 운영점을 자동으로 찾습니다
- **보류 처리 정책** — 보류를 "양성 의심으로 2차 확인"으로 볼지, "분석에서 제외"할지.
  이 선택이 지표를 크게 바꿉니다
- **신뢰도 캘리브레이션** — 구간별 실측 정확도 표와 ECE. softmax가 얼마나 과신하는지
  숫자로 나옵니다
- **가장 자주 헷갈리는 조합** — 클래스를 합칠 근거가 됩니다
- **실패 사례 갤러리** — 확신하며 틀린 순서. 약점을 먼저 드러내는 편이 신뢰를 얻습니다
- CSV 내보내기

### 설정 탭

모델 파이프라인(게이트키퍼 / 주분류기 / 앙상블), 판정 정책 슬라이더, 품질 게이트
임계값(웹캠 실시간 수치를 보며 조정), 저장 데이터 관리.

**앙상블**: 서로 다른 전처리로 학습한 모델을 여러 개 등록하면 가중 소프트보팅합니다.
원본 / CLAHE / ROI 확대본으로 각각 학습한 3개를 넣으면 단일 모델보다 안정적입니다.
클래스 집합이 다르면 경고합니다.

## 6. 발표에서 쓸 카드

이 킷이 만들어 주는, 다른 팀에 없을 것들:

1. **"TM이 말한 정확도가 아니라 우리가 검증한 정확도"** — 원본 단위 홀드아웃으로
   누출을 차단하고 자체 평가했다는 서사
2. **"모델이 무엇을 보는지 확인했다"** — 오클루전 히트맵, 그리고 지름길 학습을
   발견해 전처리로 제거한 이력
3. **"softmax는 확률이 아니다"** — 캘리브레이션 표와 ECE 수치
4. **"임계값은 임상 판단이다"** — 민감도-특이도 트레이드오프를 슬라이더로 시연하며
   *"놓치면 위험한 소견이므로 민감도를 우선해 임계값을 0.55로 낮췄고, 그 대가로
   위양성이 늘어 2차 확인 단계를 붙였습니다"*
5. **"모델이 모른다고 말할 수 있게 만들었다"** — 무효 클래스 + 게이트키퍼 + 4단 관문.
   심사위원이 웹캠에 손을 흔들어도 무너지지 않는 것을 직접 보여 주기
6. **"영상은 어디로도 전송되지 않는다"** — 서버가 없는 구조가 의료정보 보호에서 강점
7. **실패 사례를 스스로 전시** — 심사위원이 찾아내기 전에

## 7. 트러블슈팅

| 증상 | 원인과 해결 |
|---|---|
| 카메라가 안 열림 | `file://`로 열었을 가능성. `./serve.sh` 후 `localhost`로 접속 |
| 모델 로드 실패 | URL 오타 / 트레일링 슬래시 (자동 보정됨) / TM에서 Upload를 안 했음 |
| 클래스 불일치 경고 | 설정 탭 리포트가 어느 이름이 다른지 알려 줍니다. `project.config.js` 수정 |
| 아무 걸 찍어도 특정 클래스가 나옴 | 무효 클래스가 없음. `negatives.py` 실행 후 재학습 |
| 웹캠 정확도가 업로드보다 크게 나쁨 | 도메인 갭. `augment.py --webcam-degrade` + `recapture.py` |
| 홀드아웃 정확도가 TM 정확도보다 훨씬 낮음 | **정상입니다.** TM 쪽이 누출로 부풀려진 값 |
| 홀드아웃 폴더 인식 실패 | 폴더명 = 클래스 id. 대소문자까지 일치해야 합니다 |
| 히트맵이 전부 비어 있음 | 어느 칸을 가려도 예측이 안 바뀜 = 특정 근거 없이 판정. 학습 재검토 |
| 실시간 판독이 버벅임 | 설정 탭에서 추론 간격을 300~500ms로 올리세요 |
| 브라우저 저장 용량 초과 | 이력 탭에서 삭제, 또는 설정 탭 → 전체 초기화 |

## 9. 알려진 한계

- TM은 **분류만** 가능합니다. 병변의 위치·개수·영역이 필요한 주제는 이 킷으로
  해결되지 않습니다. 주제 선정 단계에서 통과시켜야 하는 조건입니다.
- 캘리브레이션과 임계값은 홀드아웃 표본이 충분해야 의미가 있습니다. 클래스당
  20건 미만이면 수치를 신뢰하지 마세요 (평가 탭이 경고합니다).
- 오클루전 히트맵은 8×8 격자 해상도입니다. 작은 병변의 정확한 경계는 알 수 없고,
  "어느 사분면을 보는가" 수준의 해상도입니다.
- 이력과 보정표는 `localStorage`에 저장되므로 브라우저를 바꾸면 사라집니다.
